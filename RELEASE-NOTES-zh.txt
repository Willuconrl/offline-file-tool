二、GitHub 上传方式（重要）
---------------------------
· 仓库内容（源码 / ui / scripts / packaging / 说明文档）：直接提交，见本 _upload 目录。
· 二进制（两个 exe 与完整版 ZIP）：作为 **Release 资产** 上传。
  原因：GitHub 仓库单文件上限 100 MB，而完整版 ZIP 为 169 MB、ffmpeg.exe 为 212 MB，
  提交进仓库会直接失败；Release 资产单文件上限 2 GB，适合放二进制。
· 仓库 .gitignore 已排除 /dist 与 /ffmpeg，请勿把 400+ MB 的二进制提交进 Git 历史。

三、许可证合规（随附 FFmpeg 时必读）
------------------------------------
· 随附的 FFmpeg 启用了 --enable-gpl --enable-version3，即 **GPL v3** 构建。
· 它以独立可执行程序的形式随包分发，由主程序以命令行方式调用，**未链接进主程序**，
  属于"聚合分发"（separate programs on the same medium）。
  因此：FFmpeg 适用 GPL v3（附 LICENSES/GPL-3.0.txt 即可），主程序仍为 MIT。
· 切勿将 FFmpeg 静态链接进主程序 —— 那样整个软件必须按 GPL 发布，MIT 授权将被覆盖。
· 用户在包内可自行替换 ffmpeg/bin 下的可执行文件，满足 GPL 的可替换性要求。

四、复现打包
------------
    pwsh -File scripts/package-release.ps1
脚本会重新生成暂存目录与 ZIP，复制 LICENSE / 说明文档 / GPL-3.0 全文，生成 SHA256SUMS.txt，
并对 GPLv3 抬头与结尾做校验、解压后实跑 ffmpeg -version 与 ffprobe -version 自检。

五、已知提示
------------
· 未购买代码签名证书，首次运行会出现 SmartScreen "Windows 已保护你的电脑"提示，
  需点"更多信息 → 仍要运行"；README-zh.txt 中已说明。
· 需要系统具备 WebView2 运行时（Win11 / 较新 Win10 已内置）。
· 完整版 ZIP 解压后约 434 MB，建议解压到非系统盘。
